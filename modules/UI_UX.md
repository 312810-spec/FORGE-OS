# FORGE UI + UX v0.1.0

**Callouts:** `UI:` composition/visual design; `UX:` behaviors/journeys; `UI + UX:` combined audit or implementation.

Read the current project's design system and any available DesignMotion-Philosophy-FORGE-Research.md before using external inspiration. Do not claim access to documents not actually loaded.

- Establish operator task, device, screen, primary action, dependencies, costly errors and success signal.
- Map major journeys, information architecture, navigation, content hierarchy, interaction/focus and touch/keyboard behavior.
- Assess loading, empty, error, permission, offline, conflict, save, success, undo and recovery states.
- Review contrast, typography, breakpoints, reduced motion, accessible names, target sizes and progressive disclosure.
- For audits, give evidence, affected workflow, severity, proposed change and test method; separate observed defects from advice.
- For authorized implementation: reuse existing components/tokens, work incrementally, run tests, inspect actual rendering when available, verify focus and failure paths, and label untested behavior.
- Never infer hidden app internals solely from screenshots; never claim a save or approval until backend or app evidence confirms it.
- Screenshots are optional unless expressly requested or essential to diagnosing layout. Avoid gratuitous screenshots.

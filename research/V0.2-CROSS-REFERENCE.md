## Reverse-engineered integration model (functional architecture, not proprietary internal code)
- Selection: user callout → parser → registry → module file paths → task-specific read.
- Evidence: accessible primary sources → provenance / claims → independent checks → release gate.
- Continuity: task checkpoint → changed-source check → authorized resume.
- Automation: GitHub Actions schedule/manual dispatch → deterministic validator/tests → execution report.
- Human control: no hidden multi-project access, no unapproved deployment, no automatic merge.

## Benchmark plan
Compare v0.1 vs v0.2 on identical: unrecognized prefix; ambiguous intent; blocked browser; mixed read+write; stale project handoff; invalid registry; recovery checkpoint; critical assessment with erroneous answer key. Report correctness, tool count, latency if measured, reproducibility, and regressions. Do not claim quality gains merely from new architecture.
